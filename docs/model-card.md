# Model card: credit-logit-1.0.0

## Intended use

Prototype ranking and explanation of consented new-to-credit applications. The model estimates repayment probability from normalized financial and behavioral aggregates. It is one input to a policy and human-review workflow, not an autonomous lender.

## Model and data

- Type: non-negative, L2-regularized logistic regression scorecard.
- Training: 6,000 deterministic synthetic profiles.
- Validation: 2,000 deterministic synthetic profiles.
- Features: income stability, utility history, cash-flow stability, affordability, mobile-account tenure, balance buffer, device trust, identity consistency, access behavior, location stability, and loan scale.
- Excluded: gender, religion, caste, precise location, contact-list contents, message contents, and social-media content.

## Validation result

Generated by `python3 ml/train_model.py`:

- ROC-AUC: 0.8344
- Precision: 0.5959 at the validation threshold
- Recall: 0.6008 at the validation threshold
- Accuracy: 0.8060
- Equal-opportunity gap: 0.0166 across synthetic evaluation groups

These values only show that the prototype pipeline works. Synthetic metrics are not evidence of real-world creditworthiness, fairness, calibration, or regulatory compliance.

## Decision thresholds

- Approve candidate: repayment probability >= 0.74, fraud risk < 0.35, and no policy review/fail.
- Human review: repayment probability >= 0.47 or a review-level policy/fraud signal.
- Decline candidate: repayment probability < 0.47, fraud risk >= 0.65, or a hard policy failure.

The UI labels these as recommendations. A human owns the final action.

## Explainability

Reason codes are calculated from actual logistic feature contributions and paired with the observed aggregate. The narrative layer can only summarize these structured reasons and policy checks.

## Required before real use

Representative consented data, legal review, leakage tests, calibration, reject-inference strategy, subgroup sample-size analysis, stability by time cohort, challenger evaluation, adverse-action mapping, monitoring thresholds, override governance, incident response, and independent model validation.
